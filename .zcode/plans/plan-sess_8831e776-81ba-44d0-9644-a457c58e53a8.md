## 修复方案（第二轮：编辑器乱跳 + VSCode 搜索 + class 跳转）

### 问题 1：编辑器输入乱跳（最严重）

**根因**：`watch(() => props.content)` 回环未彻底解决。
- 用户输入 `a` -> `updateListener` -> `setContent("a")` -> `tab.content="a"` -> `props.content="a"`
- 用户继续输入 `b`（doc 此时是 `"ab"`）-> Vue watch 触发，`next="a"`(旧 batch 值), `current="ab"` -> `next !== current` -> **dispatch 全文替换为 `"a"`** -> 覆盖用户输入 + 光标错位

**彻底修复（断环 + 外部修改标记）**：
- `stores/editor.ts`：新增 `pendingExternalUpdate: Set<string>`，`markExternalUpdate(path)` 标记某文件即将被外部修改
- `syncFromDisk` / `reloadAfterDiscard` / `formatDocument`（格式化分支）/ `renameSymbol` 在改 `tab.content` 前调 `markExternalUpdate`
- `CodeMirrorEditor.vue` 的 `watch(() => props.content)`：**只在 `editorStore.consumeExternalUpdate(props.path)` 返回 true 时才 dispatch**；否则 return（用户输入回声被忽略）
- 删掉之前加的 `selection: { anchor, head }` 复杂逻辑（断环后不再需要，因为 watcher 只在外部修改时跑，此时光标确实该重置）
- `updateListener` 的 `setContent` 调用**不标记**（这是 CM 自身变化回声，不该回流）

### 问题 2：VSCode 风格搜索面板（恢复 MiroFindPanel）

**根因**：之前移除了 `createPanel: createMiroFindPanel`，改用内置 panel。但内置 panel 样式不是 VSCode 风格。原 MiroFindPanel 的真正 bug 是 `openFindPanel` 在 `openSearchPanel` 后立即 `panelByView.get`，但 panel 还没 mount（CM 异步调度）。

**修复**：
- `CodeMirrorEditor.vue`：恢复 `search({ top: true, createPanel: createMiroFindPanel })`
- `findPanel.ts`：恢复完整 MiroFindPanel 类（从 git 历史还原）
- 修复时序 bug：`openFindPanel`/`openFindReplacePanel` 用 `requestAnimationFrame` 延迟一帧后再 `panelByView.get` + `setQuery`/`setReplaceVisible`/`focusReplace`
- 恢复 `CodeMirrorEditor.vue` 里被删的 `.miro-find-*` CSS（从 git 历史还原）

### 问题 3：class 跳转到样式区域定义

**根因**：`documentSymbols.ts` 的 `DEF_PATTERNS` 只识别 JS/TS 符号，不识别 CSS 选择器。Vue `<style>` 段的 `.foo { }` 无法被索引为符号定义。

**修复**：
- `documentSymbols.ts` 新增 `CSS_CLASS_RE`：`/^\s*\.([A-Za-z_][\w-]*)\s*(?:,|\{)/`，匹配 `.foo {` / `.foo,` / `.foo.bar {`（取首个 class）
- `indexLines` 增加 CSS 识别分支：对每行先试 JS DEF_PATTERNS，未命中再试 CSS_CLASS_RE（kind="class"）
- `indexDocumentSymbols` 对 .vue 文件：除了 script 段，也扫描 `<style>` 段（提取行号偏移）
- `findSymbolDefinition` 已在上轮改为「脚本段未命中回退全文」，CSS class 会自然被全文索引命中
- 纯 .css/.scss/.less 文件：直接全文索引，CSS class 自然支持
- `SymbolKind` 已有 `"class"`，无需扩展类型
