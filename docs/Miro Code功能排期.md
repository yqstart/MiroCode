# Miro Code 功能排期

> 对应文档：《Miro Code技术架构文档》《Miro Code视觉与主题规范》《Miro Code代码编辑器需求文档》  
> 假设：**1–2 名全栈**（前端为主 + 可写 Tauri/Rust），全职推进。  
> 总周期建议：**约 14–16 周** 完成需求主路径；冲突可视化与深度语言能力可滚动迭代。

---

## 1. 排期总览

```
W1–W2   里程碑 M0  工程地基 + 主题壳
W3–W5   里程碑 M1  工作区 + 资源管理器 + 编辑闭环
W6–W7   里程碑 M2  双检索（文件查找 / 内容搜索）
W8–W10  里程碑 M3  Git L1/L2
W11–W13 里程碑 M4  全语法能力加深 + Markdown 预览
W14–W15 里程碑 M5  Git L3 + 体验打磨 + 打包
W16+    里程碑 M6  预留：LSP / AI / MCP（需求外，设计稿预留）
```

| 里程碑 | 周期 | 目标一句话 | 可演示结果 |
|---|---|---|---|
| M0 | 2 周 | 跑起来、好看 | 深浅主题壳 + 空布局 |
| M1 | 3 周 | 能打开项目写代码 | 树 + 标签 + 存盘 + 基础高亮 |
| M2 | 2 周 | 能找到文件和内容 | 文件查找 + 全局搜索/替换 |

## 2. 优先级定义

| 级 | 含义 |
|---|---|
| P0 | 无则不成编辑器 |
| P1 | 需求明确且高频，主路径必达 |
| P2 | 需求有，可后置一到两个迭代 |
| P3 | 设计稿出现但需求未强制 / 远期 |

## 3. 分阶段详细排期

### M0｜工程地基与视觉壳（第 1–2 周）

**目标**：可安装运行的 Tauri 应用；VSCode 式布局骨架；Dawn / Adnify Dark 可切换。

| 任务 | 优先级 | 产出 |
|---|---|---|
| 初始化 Tauri 2 + Vue3 + TS + pnpm | P0 | 桌面窗体跑通 |
| AppShell：ActivityBar / SideBar / EditorArea / StatusBar | P0 | 可折叠侧栏、可拖拽宽度 |
| 主题系统：CSS 变量 + `adnify-dark` / `dawn` | P0 | 一键切换，无闪烁硬切 |
| 设置弹层骨架（对齐 theme 信息架构） | P1 | 编辑器页：主题、字号、Tab、换行、行号 |
| 配置持久化（主题/布局/编辑器偏好） | P1 | 重启后恢复 |
| 系统菜单最低集（打开文件夹、保存、设置） | P0 | 可打开空工作区 |
| 跨平台本地跑通（至少 macOS + 其一） | P1 | 开发构建脚本 |

**验收**：

- 启动到可交互 ≤ 2s（空项目）  
- 深浅主题与截图色系一致（紫强调 / 蓝强调）  
- 布局折叠与宽度刷新后仍在  

**不做**：真实文件树、Git、搜索、语法智能。

---

### M1｜工作区 · 资源管理器 · 编辑闭环（第 3–5 周）

**目标**：打开本地文件夹 → 浏览/操作文件 → 多标签编辑 → 保存；对标 VSCode 资源管理器主路径。

| 任务 | 优先级 | 产出 |
|---|---|---|
| 打开文件夹 / 最近项目 | P0 | 工作区根目录 |
| 文件树虚拟列表 + 懒加载子目录 | P0 | 千级文件可展开 |
| 新建/重命名/删除/复制/粘贴/移动 | P0 | 与 VSCode 操作直觉一致 |
| 默认忽略 `node_modules` / `.git` / `dist` + 自定义忽略 | P1 | 树干净 |
| 关键词过滤树节点 | P1 | 快速缩树 |
| 右键菜单（复制路径、在树中显示等） | P1 | 基础集 |
| CodeMirror 6 接入 + 多标签 + 脏标记 | P0 | 编辑存盘 |
| 文件变更监听与外部更新提示 | P1 | 防覆盖丢数据 |
| JS/TS/JSON/Markdown/HTML/CSS 基础高亮 | P0 | 可读可写 |
| 状态栏：类型、编码、行列 | P1 | 信息正确 |
| 树与标签双向定位高亮 | P1 | 打开文件树高亮；保存后状态刷新 |

**验收**：

- 用真实前端仓库走通「打开 → 改 → 存」  
- 删除/重命名有确认，路径不逃出工作区  

**不做**：Git 状态角标可先占位；全局搜索；分支操作。

---

### M2｜双检索体系（第 6–7 周）

**目标**：WebStorm 式「文件查找」+「全局内容搜索/替换」。

| 任务 | 优先级 | 产出 |
|---|---|---|
| 文件查找弹层（模糊名、后缀、历史、跳转） | P0 | 快捷键唤起 |
| 全局内容搜索面板（大小写、排除目录、上下文行） | P0 | 流式结果 |
| 搜索结果点击定位到行列 | P0 | 打开并选中 |
| 批量替换 + 预览确认 | P1 | 安全替换 |
| 文件类型筛选 / 范围限定 | P1 | 降噪 |
| 搜索进行中可取消 | P2 | 大项目友好 |

**验收**：

- 在中型项目（≥1k 文件）搜索不卡死 UI  
- 替换有预览，误操作可感知  

---

### M3｜Git L1 / L2（第 8–10 周）

**目标**：无需命令行完成日常提交与同步；交互对标 WebStorm 变更列表。

| 任务 | 优先级 | 产出 |
|---|---|---|
| 仓库检测 / init / 关联远程 | P0 | 无仓库可初始化 |
| status 可视化（未跟踪/修改/暂存/删除） | P0 | 变更列表 |
| stage / unstage（单文件与批量） | P0 | 暂存区 |
| commit（备注、选文件提交） | P0 | 本地提交 |
| 分支：查看、新建、切换、删除、重命名 | P0 | 分支管理 |
| diff 查看（未提交变更） | P1 | 提交前可读 |
| log 列表（作者/时间/说明/涉及文件） | P1 | 历史浏览 |
| pull / push（含失败提示） | P0 | 远程同步 |
| stash 暂存与恢复 | P1 | 切支不丢活 |
| 资源树 / 状态栏 Git 状态角标与当前分支 | P1 | 全局感知 |
| 强制推送二次确认 | P2 | 安全阀 |

**验收**：

- 完成「改代码 → 暂存 → 提交 → 推送」闭环  
- 切换分支后工作区与树状态正确刷新  

**不做**：三路冲突合并编辑器（放到 M5）。

---

### M4｜全语法能力加深（第 11–13 周）

**目标**：需求所列语法具备「高亮、折叠、校验、补全、跳转」五能力；深度按语法分级。

#### 4.1 通用能力（全语法）

| 任务 | 优先级 |
|---|---|
| 代码折叠（语法块 / 全折全开） | P0 |
| 基础补全（关键字、片段） | P0 |
| 诊断展示（行内红线 + hover + 状态栏计数） | P0 |
| 引用跳转：相对路径 / import 文件跳转 + 返回 | P0 |
| 编辑器设置生效（字号、Tab、换行、行号） | P0 |

#### 4.2 分语法目标

| 语法 | 一期达标（M4） | 可后置（P2） |
|---|---|---|
| JavaScript / TypeScript | 高亮、折叠、基础校验/补全、符号与模块跳转 | 完整类型系统 |
| Vue SFC | 三区高亮、标签折叠、组件路径跳转、指令补全 | props 深度校验 |
| HTML / CSS / Sass | 高亮、折叠、属性补全、基础校验 | 复杂选择器智能 |
| JSON / Env | 严格格式校验、键值高亮、Env 重复键检测 | JSON Schema 全量 |
| Markdown | 高亮、折叠、预览 | 所见即所得 |
| YAML / XML | 高亮、折叠、格式校验、基础补全 | 高级 schema |
| Tailwind | 默认工具类高亮 + 补全 | 自定义 config 完整解析 |

**验收**：

- 用自带示例项目打开以上语法，五能力可点检  
- Markdown 可预览  
- 主题切换时高亮配色同步  

---

### M5｜Git L3 · 打磨 · 发布（第 14–15 周）

**目标**：冲突可处理；性能与体验达标；产出跨平台安装包。

| 任务 | 优先级 | 产出 |
|---|---|---|
| merge + 冲突文件列表 | P0 | 可感知冲突 |
| 冲突对比视图（保留本地/远程/手动） | P0 | 可解决主路径 |
| 重置工作区 / 撤销最近提交（确认） | P1 | 危险操作完备 |
| 回滚到指定版本（谨慎确认） | P2 | 历史恢复 |
| 性能验收与优化（启动、大目录、搜索） | P0 | 对照非功能需求 |
| 错误文案与空状态打磨 | P1 | 体验完整 |
| 布局/快捷键基础集文档化 | P1 | 使用说明 |
| Windows / macOS / Linux 构建脚本与安装包 | P0 | 可分发 |

**验收清单（发布门禁）**：

| 项 | 标准 |
|---|---|
| 启动 | 空工作区 ≤ 2s 可交互 |
| 大项目 | 千级文件树展开无明显冻帧 |
| 内存 | 同场景主观/采样低于 VSCode |
| 主题 | Dawn / Adnify Dark 完整可用 |
| 主路径 | 打开项目、编辑、搜索、Git 日常、打包安装 |
| 范围外未污染 | 未强行塞入未完成的 AI/MCP |

## 7. 范围控制原则

1. **先闭环后深度**：能打开、能改、能搜、能提交，再抠 Vue/TS 智能。  
2. **视觉不欠债**：M0 就把双主题做对，避免后期返工。  
3. **Git 分层**：日常开发 L1/L2 优先于冲突神器。  
4. **设计稿 ≠ 需求**：AI/MCP 只预留入口，不占主航道工期。  
5. **延期时砍 P2 不砍 P0**：例如先砍 stash/强制推送/Cyberpunk，不砍存盘与提交。
