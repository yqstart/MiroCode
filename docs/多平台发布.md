# 多平台发布（GitHub Actions）

本机只有 macOS 时，用 Actions 云端分别构建 macOS / Windows / Linux，并上传到 GitHub Release。

工作流文件：`.github/workflows/release.yml`（基于官方 [tauri-action](https://github.com/tauri-apps/tauri-action)）。

## 构建矩阵

| Runner | 产物目标 |
|---|---|
| `macos-latest` | Apple Silicon（`aarch64-apple-darwin`）→ `.dmg` |
| `macos-latest` | Intel（`x86_64-apple-darwin`）→ `.dmg` |
| `ubuntu-22.04` | Linux x64 → `.deb` / `.AppImage` 等 |
| `windows-latest` | Windows x64 → `.msi` / `.exe` 等 |

当前**不做** Apple 公证与 Windows 代码签名（可后置到仓库 Secrets）。

## 发版步骤

### 方式 A：打版本标签（推荐）

1. 确认 `package.json` 与 `src-tauri/tauri.conf.json` 的 `version` 一致（如 `0.1.1`）
2. 提交并推送到 `master`
3. 打标签并推送：

```bash
git tag v0.1.1
git push origin v0.1.1
```

4. 打开仓库 **Actions → Release**，等待 4 个 job 全绿
5. 打开 **Releases**，对应 `v0.1.1` 下应出现各平台 Assets

标签名须为 `v` + 配置里的版本号（工作流使用 `v__VERSION__`，`__VERSION__` 由 `tauri.conf.json` 填充）。

### 方式 B：手动触发（给已有 Release 补包）

例如已有手建的 `v0.1.0`、缺安装包：

1. 确认当前 `master` 上 `tauri.conf.json` 的 `version` 仍是 `0.1.0`（与 tag 一致）
2. **Actions → Release → Run workflow**
3. 跑完后 Assets 会挂到已有 `v0.1.0` Release

若手动触发时配置版本已改成 `0.1.1`，会去找/创建 `v0.1.1`，而不是补 `v0.1.0`。

## 仓库权限（必查一次）

**Settings → Actions → General → Workflow permissions**

- 勾选 **Read and write permissions**
- 保存

否则 `tauri-action` 上传 Release 会报 `Resource not accessible by integration`。

## 以后加签名（可选）

| 平台 | 需要 |
|---|---|
| macOS | Apple Developer 证书 + 公证相关 Secrets（见 [Tauri 签名文档](https://v2.tauri.app/distribute/sign-macos/)） |
| Windows | 代码签名证书 / Azure Trusted Signing 等 |

未配置前，用户安装时可能看到系统安全提示，可在 Release 说明中写明「右键打开 / 仍要打开」。
