> 面向后续接手的人类开发者与 Agent。

| 项 | 说明 |
|---|---|
| 产品名 | **Miro Code**（米罗编辑器） |

## 3. 本地开发（最短路径）

### 3.1 环境

| 工具 | 建议 |
|---|---|
| Node.js | 20 LTS+ |
| pnpm | 9+ |
| Rust | stable（1.80+） |
| 系统 | macOS / Windows / Linux 桌面 |

Tauri 系统依赖见：https://v2.tauri.app/start/prerequisites/

### 3.2 命令

```bash
git clone https://github.com/yqstart/MiroCode.git
cd MiroCode
pnpm install
pnpm tauri:dev          # 桌面开发（必需：终端/SSH/文件监视依赖壳）
pnpm build              # 前端类型检查 + Vite 打包
cargo check --manifest-path src-tauri/Cargo.toml
```

验收样例：启动后打开仓库内 `examples/playground`（若存在）。

> **注意**：纯 `pnpm dev`（浏览器）无法完整验证 PTY / SSH / 原生对话框 / 更新；日常功能请用 `pnpm tauri:dev`。

### 3.3 包管理与脚本

- 包管理：**pnpm**（`pnpm-lock.yaml` 已入库，CI 用 `--frozen-lockfile`）
- 常用脚本见根目录 `package.json`：`dev` / `build` / `tauri:dev` / `tauri:build`
- 发版说明预览：`node scripts/release-notes.mjs [version]`

## 4. 源码地图（改哪里）

```
src/
  app/                 # 壳：AppShell、TitleBar、ActivityBar、SideBar、EditorArea、StatusBar
  features/
    explorer/          # 资源树（含 pointer 拖拽移动）
    editor/            # CodeMirror、查找替换、主题、符号、导航、ESLint/Prettier
    git/               # Commit 侧栏、Git Log、Branches、冲突、Rebase
    search/            # 快速打开 / 全局查找替换
    sessions/          # 本地终端、SSH、SFTP、输入桥、终端主题
    settings/          # 设置弹层（含检查更新）
  stores/              # Pinia：workspace / editor / git / sessions / settings / …
  styles/              # tokens、themes、global
  shared/              # fs、changelog、appUpdate、对话框、SSH API 封装等
  i18n/                # zh-CN / en-US（界面文案只走这里）
src-tauri/
  src/commands/        # fs / git / search / ssh 等 Rust 命令
  tauri.conf.json      # 版本号、updater pubkey/endpoints、打包
.github/workflows/
  ci.yml               # 前端 build + Rust check
  release.yml          # 多平台构建 + GitHub Release + latest.json
scripts/
  release-notes.mjs    # CHANGELOG → Release 正文
```

| 要改的能力 | 优先看 |
|---|---|
| 编辑器行为 / 快捷键 / 查找 | `src/features/editor/*`、`CodeMirrorEditor.vue` |
| 跳转定义 / import | `navigation.ts`、`documentSymbols.ts`、`shared/importReferences.ts`、`shared/fs.ts`（`resolveRelativePath`） |
| 资源树拖拽 / 文件操作 | `features/explorer/ExplorerPanel.vue`、`stores/workspace.ts` |

| 终端 / SSH / SFTP | `features/sessions/*`、`stores/sessions.ts`、`src-tauri/src/commands/ssh.rs` |

## 5. 工程约定（接手后务必遵守）

1. **语言**：标识符/文件名英文；UI 文案走 `src/i18n`；注释、文档、commit message **中文**。
2. **最小修改**：只改目标所需代码，禁止顺手大重构。
3. **胶水优先**：平台能力 / 成熟库 > 自研；不重复造编辑器/Git 协议栈。
4. **验证**：能 `pnpm build` / `cargo check` / 桌面手测的，不要只改提示词。
5. **不要提交密钥**：`.secrets/`、`.env`、用户凭据文件不得入库。
6. **Agent 规则**：仓库根 `AGENTS.md` + 用户全局工程规范；架构变更要回写文档。

## 6. 用户数据与密钥位置

### 6.1 用户机器上的应用数据（`~/.mirocode/`）

| 文件 | 用途 |
|---|---|
| `ssh-profiles.json` | SSH 主机列表（应用级全局） |
| `ssh-credentials.json` | 可选「记住密码」（权限 0600） |
| `known_hosts` | 应用侧主机密钥（配合 `~/.ssh/known_hosts`） |
| `git-credentials.json` | 可选 Git HTTPS 凭据 |

设置、最近项目等还可能在前端 localStorage（键前缀 `mirocode.*`）。

### 6.2 发版 / 更新签名（维护者侧）

| 项 | 说明 |
|---|---|
| 本地私钥（勿提交） | `.secrets/mirocode.key`（公钥 `.secrets/mirocode.key.pub`） |
| GitHub Secrets | `TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`（可为空串） |
| 配置中的公钥 | `src-tauri/tauri.conf.json` → `plugins.updater.pubkey` |
| 更新源 | `https://github.com/yqstart/MiroCode/releases/latest/download/latest.json` |

**丢失私钥 = 已安装用户无法再走应用内更新通道**，只能重装。交接时务必确认 Secrets 与私钥备份仍在密码管理器中。

可选 Windows 签名 Secrets（未配置则产出未签名包）：`WINDOWS_CERTIFICATE` 等，见 `docs/多平台发布.md`。

## 7. 发版标准流程（每次升版本）

1. 三处版本号保持一致：`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`
2. 更新 `CHANGELOG.md`：把 `[Unreleased]` 归入新版本节（含日期），更新文末 compare 链接
3. 预览 Release 正文：`node scripts/release-notes.mjs x.y.z`
4. 提交：`chore: 发布 vX.Y.Z`
5. 打标签并推送（触发 `.github/workflows/release.yml`）：

```bash
git tag vX.Y.Z
git push origin master
git push origin vX.Y.Z
```

6. 在 Actions 等 4 个平台 job 全绿；Releases 页应有安装包 + `latest.json`
7. Release 正文由 CI 调用 `scripts/release-notes.mjs` 从 CHANGELOG 生成（含安装说明页脚）

仓库 **Settings → Actions → General → Workflow permissions** 需勾选 **Read and write permissions**。

## 8. 已知雷区（踩过的坑，改相关代码前先读）

| 症状 | 根因 / 约定 |
|---|---|
| 编辑器右键菜单不出现 | `main.ts` 在**捕获阶段**对 `contextmenu` `preventDefault`；CodeMirror `domEventHandlers` 在 `defaultPrevented` 时**不会执行**。自定义菜单应挂在组件根节点透传，或用 `domEventObservers`，不要只靠 CM handler。 |
| 资源树拖拽不移动文件 | macOS Tauri **WKWebView HTML5 DnD 不可靠**。资源树已改用 **pointer 阈值拖放**（`ExplorerPanel.vue`）。新拖拽 UI 优先 pointer/mouse，勿假设 HTML5 DnD。 |
| SSH Vim 末行被裁切 | `FitAddon` 父元素若有 padding 会多算约 1 行。终端须：**外层 padding + 内层无 padding 挂 xterm**（`LocalTerminal.vue` / `RemoteTerminal.vue`）。勿对 viewport 强行 `overflow-y: auto`（破坏 TUI alternate buffer）。 |
| import 跳转失败（尤其 `../`） | 后端 `path_exists` **拒绝含 `..` 组件的路径**。必须先 `resolveRelativePath` 规范化，再按扩展名 + `pathExists` 解析（`shared/fs.ts` / `importReferences.ts`）。 |
| 更新说明只显示版本标题 | CHANGELOG 节提取**不能**在 `/m` 下用 `$` 作节尾（会在标题行末截断）。正确实现见 `shared/changelog.ts` 与 `scripts/release-notes.mjs`。 |
| 查找面板空白 | 曾误把 `.miro-find-row` 写成 `display:none`。查找行须始终 `display:flex`，仅 `.miro-find-replace-row.is-collapsed` 隐藏。 |
| macOS 更新后无法启动 | 曾错误动态链 Homebrew OpenSSL。`git2` / `ssh2` 必须 **vendored OpenSSL**（见 `Cargo.toml`），勿改回系统动态库。 |
| 选区比相同文本匹配更暗 | `selection` 对比度须高于 `selectionMatch` / searchMatch（`features/editor/theme.ts`）。 |
| CI Intel macOS OpenSSL | Release 矩阵用 `macos-15-intel` 原生构建，避免 ARM 交叉编译 openssl-sys。 |

## 9. 当前能力快照（v0.9.0）

已较完整：

- 工作区资源树、外部文件监听、右键、pointer 拖拽移动 + 可选更新 import
- CodeMirror 编辑：高亮、折叠、查找替换（VS Code 快捷键）、格式化（Prettier）、ESLint、符号与相对 import 跳转
- Git：Commit 侧栏、编辑区 Diff、Git Log、Branches、Stash、Rebase/冲突基础路径
- 会话：本地 PTY、SSH Shell、SFTP（含远程文件编辑 `miro-sftp://`）
- 主题四套；i18n 中/英；GitHub Release 自动更新

明显缺口（后续可排期）：

- **完整 LSP**（**二期已接入**）：通过 Rust transport 层桥接 `typescript-language-server` + `@vue/language-server`（Volar），stdio JSON-RPC + Content-Length 分帧；前端 `features/lsp/` 模块封装 LanguageClient + 7 项 CodeMirror 扩展（hover/签名/补全/诊断/跳转/引用/重命名）；宿主提供 Node + 检测降级回 v1 正则方案。**历史缺口已闭环**
- **无插件体系**
- macOS **未公证** / Windows **默认可无 Authenticode**：用户可能看到安全提示（文档已有绕过说明）
- 全局搜索/索引对超大仓库仍可能偏慢（已优化：搜索命令 async 化 + 文件列表缓存 + 前端竞态保护）
- `@/` 等路径别名的 import 跳转（**已支持**：对齐 tsconfig `paths`，`@/foo` → `<root>/src/foo`，覆盖跳转/符号/引用/移动改写；非 `@` 前缀的自定义别名仍按相对路径解析）

## 10. 建议接手后的前几次任务

1. 用 `pnpm tauri:dev` 完整手测：打开文件夹 → 编辑保存 → ⌘F 查找 → Git 提交 → 本地终端 → SSH/SFTP（若有环境）。
2. 确认 GitHub Actions Secrets 仍可用；必要时用 workflow_dispatch 补包验证。
3. 读一遍 `CHANGELOG.md` 近 3 个版本，对齐产品现状与文档滞后处。
4. 若要做「大功能」：先改需求/排期文档或开 Issue，再动架构；LSP 引入需单独技术选型评审（架构文档写明一期不做自研 LSP）。
5. 修 Bug 时优先查本文第 8 节雷区，避免重复踩坑。
